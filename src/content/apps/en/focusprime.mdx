## The problem

Habit apps count streaks and punish the day you miss. Others pad the numbers with things that weren’t even due. In the end you can’t tell whether you’re doing well or just ticking boxes.

## What it does

- **Today**: what’s due, what’s optional and what’s already logged. Mark items as done, partly done or skipped, and undo at any time.
- **Habits and to-dos**: habits that repeat on the days you pick and one-off to-dos, each with its own color and icon.
- **Streaks and detail**: every habit’s current streak, its best one and the last few weeks at a glance.
- **Honest progress**: XP and levels that never go down, milestones, a year-long consistency heatmap and a completion rate that only counts what was due.
- **Goals**: targets like “50 workouts by the end of the year” that add up on their own from the linked habits.

## How it’s built

This is the second version: the first one (Next.js and Supabase) was rewritten from scratch when the product narrowed to habits and to-dos. It’s now a SPA on **React 19**, **TanStack Router** and **TanStack Query**, with Tailwind and Motion. The API runs on **Hono** and **Drizzle** over **Cloudflare D1**, and it shares Zod contracts and domain logic (recurrence, streaks, XP) with the app. Everything lives in a single **Cloudflare** Worker. Sign-in, with **Better Auth**, uses a one-time code sent by email, with no password. There are API tests on the Workers runtime and Playwright flows with axe.

## The demo

It’s the real app, API included, running inside your browser. The same Worker runs in the page on top of an SQLite database compiled to WebAssembly, so everything you do stays in your browser. You start signed in to an account with ten weeks of history. If you sign out, you can create another one with any email: the code shows up on screen, because the demo doesn’t send emails. The interface is in Spanish.
